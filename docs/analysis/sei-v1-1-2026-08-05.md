## Background

This is the v1.1 release. The site renames from **Tech Scan** to **SE Intelligence**, and shifts from a "scanning log" to a **knowledge base** with two artifact types:

- **Topics** (`/topic/<key>`) — synthesized knowledge articles with inline citations
- **Sources** (`/source/<key>`) — cited references (formerly called "entries", renamed for semantic accuracy)

The existing 23 sources remain unchanged. 3 sample topic pages are added (`system-def`, `reliab`, `dist-sys`) as the design template for the remaining 18 to follow.

This test plan covers the rename, the new architecture, the comments back-compat, and a regression test that proves the existing user-visible behavior still works.

## Plan

### Phase 1 — Schema and parser (deterministic, no browser)

1. **Parser unit tests** — assert `parseTopicPage()` produces the right structure
2. **Inline citation extraction** — assert `[<key>]` becomes `[n]` and dedup is correct
3. **Source back-compat** — assert `parseMarkdown()` still works on the 23 existing entries (no regression)
4. **Date handling** — assert `formatDate()` handles Date objects, ISO strings, year-only
5. **No phantom `__summary__`** — assert a markdown file with a blank line after the title does not produce a stray `__summary__` section

### Phase 2 — Smoke and engine (no browser)

1. **Source count** — assert 23 sources still load from `entries-index.js`
2. **Topic count** — assert 3 topic pages load from `topics-index.js`
3. **Citation integrity** — assert every citation key in every topic page resolves to a real source
4. **Forward citations** — assert every source cited by a topic page is documented as cited in that source's "Cited in" section (auto-computed)
5. **Conference sources** — assert event/track/year/authors schema still validates

### Phase 3 — Routing and views (Puppeteer, headless)

1. **Home page** — `/` loads, Knowledge base section visible, Hottest topics dashboard visible, hero visible
2. **Topics index** — `/topics` loads, shows the 3 topic cards grouped by topic
3. **Sources index** — `/sources` loads, shows 23 sources grouped by type, sorted by date
4. **Topic page** — `/topic/system-def` loads with title, summary, sections, citations as `[n]` links, references list, comments section
5. **Source page** — `/source/reliab-meta-storage-tail-aware` loads with title, summary, "Cited in" section listing `Reliability & Resilience [1]` and `Distributed Systems [3]`
6. **Legacy redirect** — `/entry/anything` redirects to `/source/anything`
7. **404s** — `/topic/does-not-exist` shows "Topic not found"
8. **404s** — `/source/does-not-exist` shows "Entry not found"
9. **Inline citation click** — clicking a `[1]` in a topic body navigates to the cited source page

### Phase 4 — Search (Puppeteer)

1. **Search by topic name** — typing "reliab" returns the topic page result (with "Topic" badge) and any sources that mention it
2. **Search by source content** — typing "MBSE" returns topic pages that cite MBSE patterns + the source itself
3. **Topic result click** — clicking a topic result navigates to `/topic/<key>` (not `/source/<key>`)
4. **Source result click** — clicking a source result navigates to `/source/<key>`

### Phase 5 — Comments (Puppeteer + API)

1. **Topic comment load** — `/topic/system-def` shows the "Comments" section with the topic-specific blurb
2. **Source comment load** — `/source/reliab-meta-storage-tail-aware` shows the "Comments" section with the source-specific blurb
3. **Submit a topic comment** — fill form, submit, verify it appears in the thread
4. **Submit a source comment** — same, on a source page
5. **Namespace isolation** — a comment posted on `/source/<key>` does NOT appear on `/topic/<key>` and vice versa
6. **Back-compat (existing comments)** — the existing comment on `system-def-mbse-patterns-2025` (from pre-v1.1) is still visible at `/source/system-def-mbse-patterns-2025` after the rename
7. **Admin view** — `/admin` lists all comments with their namespace badge (topic vs source)
8. **Admin actions** — ack / acted / reply / delete all work on both namespaces

### Phase 6 — Brand and metadata

1. **`<title>`** — every page has "SE Intelligence" in the title
2. **`<meta name="description">`** — matches the new site description
3. **Sidebar brand** — "SE Intelligence" appears in the desktop sidebar header
4. **Mobile bar** — "SE Intelligence" appears in the mobile top bar
5. **`wrangler.toml` project name** — `name = "se-intelligence"`
6. **No remaining "Tech Scan" strings** in user-visible text (search the codebase)

### Phase 7 — Regression on existing user behavior

1. **Hot-topics dashboard still renders** — recency-decay scoring unchanged
2. **Source list with triage filter** — chips still work (all / watch / read / try)
3. **Conferences route** — `/conferences` still lists the 11 conference entries
4. **About page** — `/about` still loads (no content changes)
5. **Print / download .md** — both still work on source pages
6. **Permalink to /source/ works** — `/source/<key>` is the canonical URL; old `/entry/<key>` redirects

### Phase 8 — Performance and bundle size

1. **Topic parser adds <2KB** to the bundle
2. **Topic pages load in <50ms** locally (single fetch per page)
3. **No N+1 in the sidebar** — counts computed once in `renderSidebar`
4. **Search index built once** at load time, reused on each keystroke

### T-01: Parser unit tests

A new `scripts/test-parser.js` that asserts:

```js
// parseTopicPage basics
parseTopicPage('x.md', '---\n---\n\n# Title\n\nBody').title === 'Title'

// Inline citation extraction
const t = parseTopicPage('x.md', '---\n---\n\n# T\n\nSee [foo] and [bar] then [foo] again.');
t.citations.length === 2
t.citationByKey['foo'] === 1
t.citationByKey['bar'] === 2
// Section body has [1] and [2] in place of [foo] and [bar]
t.sections[0].content.includes('[1]')
t.sections[0].content.includes('[2]')
t.sections[0].content.includes('[1] again')

// References heading is stripped (auto-replaced)
const t2 = parseTopicPage('x.md', '---\n---\n\n# T\n\n## References\n\n1. Manual\n');
t2.sections.length === 0  // no "References" section remains

// Phantom __summary__ is gone — blank line after title doesn't break parser
const t3 = parseTopicPage('x.md', '---\n---\n\n# Title\n\n## TL;DR\n\nBody');
t3.sections.map(s => s.heading).includes('__summary__') === false
t3.summary === 'Body'

// Date handling in formatDate
formatDate('2025-05-20') === 'May 20, 2025'
formatDate('2025-05-20T00:00:00.000Z') === 'May 20, 2025'
formatDate(new Date('2025-05-20T00:00:00Z')) === 'May 20, 2025'
formatDate(2024) === 'January 2024'
formatDate(null) === ''

// Topic page markdown citation
const t4 = parseTopicPage('x.md', '---\n---\n\n# T\n\n## Section\n\n[abc] is a source');
const html = topicBodyToHtml(t4.sections[0].content, t4.citationByKey);
html.includes('<sup class="cite"><a href="/source/abc">[1]</a></sup>')
```

**Expected**: 20-30 assertions, all pass.

### T-03: Routing/views (NEW)

A new `scripts/test-routes.js` that uses Puppeteer to navigate and assert DOM state.

```js
// Home
await page.goto(BASE + '/')
assert(await page.$('.topics-featured'))           // Knowledge base section
assert(await page.$('.hot-topics'))                // Dashboard
assert(await page.$('.entry-header h1'))           // Hero

// Topics index
await page.goto(BASE + '/topics')
assert((await page.$$('.topics-bucket')).length >= 1)

// Sources index
await page.goto(BASE + '/sources')
assert((await page.$$('.topics-bucket')).length >= 1)

// Topic page
await page.goto(BASE + '/topic/system-def')
assert((await page.$$eval('sup.cite a', els => els.length)) >= 5)
assert((await page.$('h1.topic-title')))
assert((await page.$('.topic-references ol')))
assert((await page.$('.comments-section')))

// Source page
await page.goto(BASE + '/source/reliab-meta-storage-tail-aware')
assert((await page.$('.cited-in-section')))
const citedInText = await page.$eval('.cited-in-section', el => el.innerText)
assert(citedInText.includes('Reliability & Resilience'))
assert(citedInText.includes('Distributed Systems'))

// Legacy redirect
await page.goto(BASE + '/entry/anything')
const finalPath = await page.evaluate(() => location.pathname)
assert(finalPath === '/source/anything')

// 404s
await page.goto(BASE + '/topic/does-not-exist')
assert((await page.$eval('h1', el => el.textContent)).includes('Topic not found'))
```

**Expected**: 15-20 assertions, all pass.

```js
// ... similar

// Namespace isolation

const sourceComment = await fetch(BASE + '/api/comments?entry=system-def&ns=source')
const topicData = await topicComment.json()
const sourceData = await sourceComment.json()
assert(topicData.comments.length !== sourceData.comments.length)  // different streams

// Back-compat: existing comment still visible
await page.goto(BASE + '/source/system-def-mbse-patterns-2025')
const oldComment = await page.$eval('.comments-thread', el => el.innerText)
// (will be empty for a fresh local wrangler dev; the test asserts the system RETURNS the
//  comment if it was posted pre-rename — for the test, we POST a comment first
//  then verify it shows up)
```

**Expected**: 8-10 assertions, all pass. Runs against `npx wrangler pages dev . --port 8788` — wrangler compiles the comments Worker, binds `COMMENTS_KV` in-memory (local mode), and the static site is served on the same port. No deployed site needed.

**Note**: The local `COMMENTS_KV` is in-memory only — comments posted during the test do not persist past `wrangler pages dev` shutdown. This is fine for tests (each run starts fresh) but means the test cannot assert "this comment persisted from yesterday."

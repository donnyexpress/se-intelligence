## Plan

### 1. Topic taxonomy — INCOSE-aligned, with conference material as first-class

**Sources used to derive this taxonomy (researched 2026-08-04):**
- **SEBoK v2.11** (Nov 2024) — 9 general knowledge areas + 26 specific. Authoritative reference, internationally recognized.
- **INCOSE SE Handbook v5.0** (2023) — life cycle processes per ISO/IEC/IEEE 15288:2023. The state-of-good-practice.
- **IS2026 paper categories** — what INCOSE itself uses to bucket submitted papers this year. This is the freshest signal of where the discipline's attention is.
- **IS2026 emphasis areas** — what they're actively soliciting: Systems Thinking, Continuous Delivery, Managing System Complexity, Agile SE, Energy Transformation, Mission Engineering, Emergency Management, New Innovative Approaches, Systems Science Foundations.
- **~30 INCOSE Working Groups** — specialized communities of practice.
- **Conference proceedings** (IS, IW, regional symposia) — openly published, goldmine for scanning.

**Design decision:** Lead with **SEBoK's 9 general knowledge areas** as the primary sidebar taxonomy (every SE practitioner recognizes them; this gives the site instant authority). Add a separate **Conference Proceedings** track so past IS/IW material is browsable, not buried. Keep the SE-from-the-trenches topics (observability, distributed systems, ML systems, security) as a secondary **Application Domains** rail — INCOSE itself treats these as cross-cutting applications, not core SE knowledge.

#### Conference Proceedings — first-class view

Conference material is treated as a peer of regular entries, not an afterthought.

- **New entry prefix**: `conf-` (e.g. `conf-is2024-mbse-patterns`).
- **New frontmatter fields**:
  - `event: IS2024` (event key from a registry in `config.js`)
  - `track: "Modelling"` (one of the IS2026 paper categories, see below)
  - `paper_id: "doi:..."` (or URL to the paper)
  - `authors: "Smith, J.; Lee, K."`
  - `year: 2024`
- **New route**: `/conferences` lists all conference entries grouped by event, descending year. Each event card shows: name, year, location, total papers indexed, link to INCOSE proceedings page.
- **Sidebar adds**: "Conferences" link → `/conferences`. On individual conference entries, a "View in INCOSE proceedings →" link goes to the canonical INCOSE page.
- **IS2026 paper categories** become the **track** taxonomy on conference entries:

| track key | track name | mapped SEBoK area |
|---|---|---|
| `innovation` | Innovation, Science, Foundations | `sys-fund` |
| `management` | Management & Enabling Disciplines | `management` |
| `uncertainty` | Managing Uncertainty | `lifecycle` |
| `modelling` | Modelling & MBSE | `system-def` |
| `org-skills` | Organization & Skills | `management` |
| `service` | Service Disciplines | `deploy-use` |
| `society` | Society & Environment | `eng-domains` |
| `conception` | System Conception | `concept-def` |
| `se-disciplines` | SE Disciplines (IV&V, PLE, Reqs) | `system-def` |

(Mirrors the official IS2026 categories document; mapping lets the home view show "recent papers in your topic area".)

#### File naming & parser mapping

- Regular entries: `entries/<topic-key>-<slug>.md` (e.g. `reliab-chaos-engineering-2026.md`).
- Conference entries: `entries/conf-<event>-<slug>.md` (e.g. `conf-is2024-mbse-patterns.md`).
- `parser.js` adds `TOPIC_BY_SUFFIX` lookup (prefix-based, matching `^[a-z\-]+-`); frontmatter `topic:` field overrides.
- Conference entries additionally parsed from a `conf-` prefix; `event` and `track` validated against the registry in `config.js`.

### 2. Entry schema (replaces playbook schema)

Per-entry frontmatter (YAML, all optional except `last_updated`):

```
---
last_updated: 2026-08-04
topic: dist-sys          # one of the 8 keys above; fallback inferred from filename
triage: read             # watch | read | try | ignore
source_type: paper       # paper | blog | talk | release-note | rfc | news | postmortem
signal: 0.85             # 0.0–1.0, curator's quality/importance score
maturity: production     # research | production | preview | deprecated
links:
  - https://jepsen.io/analyses/etcd-3-5
  - https://github.com/etcd-io/etcd/issues/13766
---

# Title of the entry

## TL;DR
One or two sentences. The actual claim, not a teaser.

## Why it matters
So what. Who should care and why.

## Key ideas
- Bullet
- Bullet

## Sources & links
- [Title](https://...)
- [Related entry]([[dist-sys-something-else]])

## My take
Honest reaction. What to do with this, who to ignore, what to skip.
```

Reserved headings the parser still strips from the body view: `TL;DR`, `Why it matters`, `Sources & links`, `My take`, `Related`, `Source`. (Same pattern as playbook; the renderer detects them and renders into the standard layout.)

### 3. Latest developments filter (new default)

- Home page default view switches from "Recent" to **"Latest developments"** — entries where `triage ∈ {watch, read, try}` AND `last_updated` within the trailing 30 days, sorted by `signal desc, last_updated desc`.
- Add a `/latest` route alias that does the same.
- Sidebar adds a "Latest (30d)" link with a count badge.
- Triage filter chips on home: `all / watch / read / try / ignore` (single-select).
- "All time" view is one click away (sidebar → "All entries").

### 7. Public-access guardrails (since comments are open)

- Add a `<meta name="robots" content="index, follow">` (already implied but explicit).
- Comments API: add a 5-second rate limit per IP via KV counter (best-effort, not a security boundary). Keeps noise down without adding auth.
- Admin: keep open for v1 (same threat model as playbook), document in README that `/admin` is currently unauthenticated.
- No PII fields added to comment schema; `name` is optional and capped at 60 chars (already in `comments.js`).

- RSS / Atom feed (mentioned in option-1 sample, not in chosen option — defer).

- Full-text search ranking (current `includes` is fine for v1).
- i18n.
- Dark/light toggle (Option 4 is dark-only; light variant is a future theme).
